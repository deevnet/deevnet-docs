## Summary

`dv02hyp002p02` runs Proxmox VE 9.2.11 on kernel 7.0.14-14, as upgraded on 2026-08-30. The
management hypervisor has run 9.2.32 since CHG-0066. This change applies the 9.2 point updates to
the tenant hypervisor so both nodes run the same release: 181 packages upgraded and 3 new, a 633 MB
download, among them `pve-manager` 9.2.32, `qemu-server` 9.2.20, `pve-qemu-kvm` 11.1.3, the SDN
packages (`libpve-network-perl` 1.6.10) and kernel 7.0.14-30.

It also brings the node's apt sources to the deb822 format, as on the management hypervisor, and
removes the leftover Bookworm and Ceph files from `sources.list.d`.

## Goal

- `pveversion` on `dv02hyp002p02` reports `pve-manager/9.2.32`, running kernel 7.0.14-30.
- `apt update` is clean, with every source in deb822 format and nothing left to upgrade.
- The node's four EVPN zones report `available`, its four vnets are present, `frr` is active and
  the `tfab` fabric is defined, as before the change.
- The test tenant's VM (`tdemo-backend`) starts and reaches the internet through its zone.

## Scope

**In scope:** Proxmox VE and Debian packages on `dv02hyp002p02`; its apt sources.
**Out of scope:** the management hypervisor, already on 9.2.32; starting any tenant's VM other than
the test tenant's; the `bpg/proxmox` provider re-baseline, which is the
[Hypervisor Platform Uplift](/docs/roadmap/site-work/mobile/hypervisor-uplift/plan/)'s last task.

## Risk and impact

| Risk | Where | Guard |
|---|---|---|
| The SDN packages render the tenant zones differently, and a tenant's network does not come up | the tenant fabric | The zones' state is recorded in Step 1 and compared in Step 5; `tdemo-backend` proves a zone end to end |
| The node does not come back after the reboot | `dv02hyp002p02` | The operator on site. The previous kernel, 7.0.14-14, stays installed and can be booted from the GRUB menu |
| The download hangs the core router | `dv02cor002p01` | Fetched in Step 2 at 1,000 KB/s, with a watchdog: the node pinging `1.1.1.1`, which crosses the router. 891 MB at that rate passed in CHG-0066 |
| A tenant loses service | tenants | None runs: every tenant VM is stopped before the change. The node's tenant DNS, API and secrets live on the management hypervisor and are untouched |

## Prerequisites

- [ ] Every tenant VM on the node stopped
- [ ] The operator on site, able to reach the node's console and restart the core router
- [ ] The node's `/etc` saved to the Builder (Step 1)

## Procedure

### Step 1: Record the state and save the configuration

No outage.

**Run** (on the node):

```bash
pveversion; uname -r
pvesh get /nodes/dv02hyp002p02/sdn/zones
pvesh get /cluster/sdn/vnets
pvesh get /cluster/sdn/fabrics/fabric
systemctl is-active frr
tar czf /root/hyp002-etc-$(date +%F).tgz /etc/pve /etc/network /etc/frr /etc/apt
```

Then copy the tarball to the Builder's `/srv/pve1-vm-backups`.

**Verify:** four zones `available`, four vnets, the `tfab` fabric, `frr` active; the tarball's
checksum matches on the Builder.

### Step 2: Download

No outage. Started with the watchdog running.

**Run:**

```bash
apt update
apt -o Acquire::http::Dl-Limit=1000 dist-upgrade --download-only
```

**Verify:** the download completes and the watchdog missed no ping.

### Step 3: Upgrade

No outage until the reboot: no guest runs.

**Run:** `apt dist-upgrade`. Keep the local copy of any configuration file it asks about, and record
the prompt under Outcome.

**Verify:** it exits without error; `dpkg --audit` is empty.

### Step 4: Sources in deb822

**Run:**

```bash
apt modernize-sources
```

Then, as on the management hypervisor: `pve-enterprise.sources` in place with `Enabled: no`
(today it is renamed `.disabled`), and `ceph.list.bookworm-backup`, `ceph.list.disabled`,
`pve-enterprise.list` (a commented Bookworm line) and the `.bak` files removed.

**Verify:** `apt update` reports no error or warning; `apt-get -s dist-upgrade` upgrades nothing.

### Step 5: Reboot and verify

**Disruptive for the node**, about two minutes.

**Run:** `reboot`.

**Verify:**
1. The node boots 7.0.14-30-pve and `pveversion` reports 9.2.32.
2. The zones, vnets, fabric and `frr` match Step 1.
3. `tdemo-backend` starts, reaches `1.1.1.1`, and is stopped again.

## Verification

The four points under Goal.

## Undo

**Steps 1, 2 and 4** need none beyond restoring the sources from the tarball. **Step 3** is not
reversed: a point release is undone forward. If the new kernel misbehaves, boot 7.0.14-14 from the
GRUB menu and pin it with `proxmox-boot-tool kernel pin 7.0.14-14-pve`.
